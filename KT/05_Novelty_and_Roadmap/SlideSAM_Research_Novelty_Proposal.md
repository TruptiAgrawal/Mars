# Research directions for our Slide-SAM project

Prepared: 26 September 2026. Scope: the working repository `Slide-SAM/Slide-SAM`.

## Recommendation

Build one coherent research story around **reliable propagation across variable slice spacing**. The best starting combination is:

1. **Physical-spacing-conditioned context adaptation**: handle changes in the anatomical distance between slices.
2. **Training on the model's own propagated prompts**: learn recovery from errors that accumulate during inference.
3. **Budgeted corrective prompting based on expected downstream improvement**: choose where a limited additional interaction will repair the most segmentation.

A fourth, smaller direction is **same-slice agreement across overlapping windows**. Implement it first as a diagnostic and simple baseline; only promote it to a central contribution if it provides evidence beyond ordinary prediction averaging.

**Immediate experimental plan:** first test the team's original ideas—automatic box padding and conditional through-plane resampling—in the controlled 2×2 study in Section 10. These are practical precursors to the larger research directions and may resolve enough of the problem to avoid unnecessary model complexity.

These are proposed research contributions, not established novel methods or promised improvements. Their specific formulations need experiments and a deeper nearest-work comparison before any “first” claim. Ordinary LoRA fine-tuning, five-fold CV, more data, and replacing the backbone are useful development steps but insufficient novelty by themselves.

## 3. Direction A — Physical-spacing-conditioned context adaptation

### Question and candidate contribution

Can a small adapter learn when neighboring slices provide useful context and when their physical separation makes them unreliable?

The candidate contribution is a context module conditioned on actual slice distances and image disagreement, with a controlled fallback toward central-slice evidence. “Use a bigger window” or “resample to isotropic voxels” are comparison baselines, not the contribution.

### Proposed flow

```text
Volume + orientation + spacing
    → select central slice and two neighbors
    → calculate physical offsets and appearance differences
    → predict neighbor gates with a small module
    → construct a residual-adjusted three-channel input
    → existing Slide-SAM encoder and decoder
    → masks at the explicitly recorded slice locations
```

A checkpoint-compatible first implementation keeps adjacent slices and transforms each neighbor as:

`adjusted_neighbor = center + gate × (neighbor − center)`

The gate lies in [0, 1] and depends on physical distance, in-plane spacing, orientation, and shallow image features. Gate=1 preserves the input; gate=0 repeats the central slice in that channel. Initialize near identity and train the new gate together with the existing adaptation parameters. This is a hypothesis: raw intensities may be too weak a signal, in which case compare a small feature-level residual module.

Later, test multiple candidate distances. If neighbors are sampled at nonadjacent indices, update decoder supervision and output placement to those exact indices; the current `idx-1:idx+2` merge cannot be reused unchanged. Never describe interpolation as recovering information missing from a thick-slice acquisition.

### Implementation locations

Extend cache metadata with physical spacing, orientation, and source indices. Add a dedicated context module in `modeling/`, wire it through `modeling/build_sam3d2.py` and `modeling/sam3d.py`, and preserve metadata in the CV loader and volume predictor. Store new caches separately from existing experiments.

### Necessary comparisons

| Variant | What it tests |
|---|---|
| Unchanged three-slice model | Reference |
| Fixed physical resampling | Whether preprocessing alone explains the gain |
| Spacing augmentation only | Whether a learned module is necessary |
| Gate using image features only | Contribution of appearance |
| Gate using physical spacing only | Contribution of geometry |
| Combined gate | Complementarity |

Evaluate native scans and paired downsampled copies at several prespecified through-plane spacings. Keep all copies of a patient in the same fold. Report Dice, surface accuracy, and performance decline versus spacing. Use correct physical coordinates and nearest-neighbor interpolation for categorical labels. Synthetic spacing experiments are robustness tests, not new independent patients; confirm on naturally varying spacing where possible.

**Effort:** medium. **Main risk:** insufficient spacing diversity in BTCV, or the gate suppressing useful neighbor information. Add an external dataset for a stronger generalization claim. Generic medical adapters already exist; distinguish this mechanism from [Medical SAM Adapter](https://doi.org/10.1016/j.media.2025.103547).

## 4. Direction B — Train recovery from propagated prompt errors

### Question and candidate contribution

Can short training trajectories reduce the gap between accurate training prompts and imperfect prompts produced during inference?

The candidate contribution is a propagation-specific curriculum that samples the model's own failures and measures how far those failures spread, including premature termination. Scheduled sampling and noise augmentation are established techniques; applying their names alone is not novelty.

### Proposed flow

```text
Training volume and target organ
    → initial clean or perturbed prompt
    → predict the current three-slice window
    → derive the next box from the predicted endpoint mask
    → predict the next window using that box
    → repeat for a short trajectory
    → supervise each output against its corresponding training label
```

Start with two propagation steps, then test four and eight. Mix ground-truth-derived and predicted prompts according to a prespecified curriculum. Detach hard masks and box coordinates between steps for the first implementation; each step still receives supervised gradients, without pretending the discrete box extraction is differentiable.

Build a balanced training distribution containing translated boxes, inward/outward edge perturbations, off-center starting slices, and real mask-derived errors. Include foreground-to-background transitions. When predictions become empty, record a termination event; use an explicitly labeled recovery policy or scheduled training reset rather than silently dropping difficult trajectories. Ground-truth rescue is permitted for training only.

A starting objective is:

`L = mean(step segmentation losses) + λ_overlap × same-slice agreement loss`

Keep agreement as an ablation, not an obligatory ingredient. Sample trajectories within the same volume, orientation, and target class; the current mask-indexed shuffled dataset needs a new sequence index.

### Implementation locations

Add a sequence dataset beside `datasets/cache_dataset3d_cv.py`. Introduce a separate rollout learner based on `core/learner3.py` and `core/learner_sub1.py`. Reuse prompt-generation logic from `core/volume_predictor.py` after extracting a shared function. Avoid placing all computation inside its `no_grad` inference methods.

### Necessary comparisons and outcomes

Compare ordinary fine-tuning, stronger random box corruption, rollout training alone, rollout plus corruption, and different trajectory lengths. Match optimization steps and report training compute so improvement is not merely extra exposure.

Measure final volume Dice and NSD, Dice versus distance from the initial prompt, early-stop frequency, organ extent recall, and propagation failure length in millimeters. Analyze both clean and noisy initial prompts. A gain only with clean boxes would not support the proposed robustness claim.

**Effort:** medium to high. **Main risk:** unstable training, feedback reinforcing mistakes, and increased memory. Detached short rollouts and gradient accumulation are reasonable first implementations; caching encoder features during trainable encoder-LoRA updates would make features stale and should be avoided.

## 5. Direction C — Spend corrective prompts where they help downstream

### Question and candidate contribution

Given a fixed interaction budget, can the model choose a slice whose correction improves a substantial remaining part of the volume?

The proposed contribution is **expected downstream benefit per unit interaction cost**, rather than simply selecting the most uncertain pixel or slice. This distinction must be tested: a locally ambiguous slice may be less valuable than an earlier propagation bottleneck.

### Proposed flow

```text
One initial user prompt
    → propagate normally
    → collect overlap disagreement, IoU score, stability, and geometry changes
    → estimate downstream improvement from correcting each candidate slice
    → select the best candidate under the remaining budget
    → obtain one additional user prompt
    → re-propagate the affected region
    → stop at budget exhaustion or a validated stopping criterion
```

Generate training targets on training volumes only: simulate one correction at a candidate slice, re-run propagation, and calculate the resulting volume-quality improvement. Fit a small benefit predictor using information available before correction. Ground truth provides the training target and simulated user's response, not the test-time candidate ranking.

Initially treat every box as equal cost. Only claim time-aware selection after measuring actual drawing/inspection time. Keep the selector small because 30 BTCV volumes provide limited independent training examples despite many slices.

### Implementation locations

Expose per-window records from `core/volume_predictor.py`, then add a separate controller, such as `core/prompt_controller.py`. Extend evaluation to replay an identical initial prompt and a fixed budget for each method. Record requested slices, prompt types, correction costs, and every intermediate prediction.

### Necessary comparisons

Evaluate total budgets of 1, 2, 3, and 5 boxes per organ-volume, including the first box. Compare uniformly spaced, random, lowest-stability, greatest-overlap-disagreement, and learned downstream-benefit selection. A ground-truth best-slice selector is an oracle upper bound only.

Report Dice-versus-prompt curves, their normalized area over the fixed budget range, correction success rate, compute per correction, and prompts required to reach a prespecified quality target. Treat unattained targets as failures, not discarded cases. Report a separate matched point-prompt track where supported; a box and a click are different forms of supervision.

**Effort:** medium to high, with significant offline target-generation cost. **Main risk:** benefit targets overfit to particular organs or folds. Validate whether the selector outperforms a simple uncertainty heuristic on unseen patients and organs.

**Overlap warning:** uncertainty-driven slice annotation is established, for example [USS](https://arxiv.org/abs/2109.14879). [MAUP](https://papers.miccai.org/miccai-2025/0532-Paper3542.html) also uses adaptive uncertainty-aware prompting. These are reasons to focus the claim on downstream correction value and interaction budgets, not uncertainty alone.

## 6. Direction D — Agreement for the same slice across overlapping windows

### Question and candidate contribution

Can disagreement between predictions of the **same physical slice**, made from different neighboring windows, detect and reduce propagation drift?

This is different from forcing two adjacent slices to have identical masks, which can erase legitimate anatomical change. The strongest prospective claim would combine role-specific reliability (central versus side output), physical distance, and a tested failure-detection mechanism. Simple mean fusion is a baseline and may be all that is needed.

### Proposed flow

```text
Overlapping windows
    → keep each mask logit and its source/target slice IDs
    → group predictions referring to the same physical slice
    → calculate disagreement and role-specific reliability
    → fuse probabilities with normalized weights
    → threshold once after fusion
```

Train with same-slice consistency only for the same target organ and aligned coordinates. Use supervised segmentation alongside consistency to prevent agreement on the wrong answer. A detached teacher prediction or confidence gate can reduce confirmation bias, but must be ablated.

### Implementation and evaluation

Change `merge_to_mask3d`/`postprocess_3d` to support a separate sum-of-weighted-probabilities and sum-of-weights accumulator. Retain the original union as a selectable reference. Add paired-window samples and an optional loss in `core/loss.py`.

Compare union, central-output-only, unweighted mean, calibrated role-weighted fusion, and fusion plus consistency training. Report false-positive volume, boundary accuracy, organ extent, and agreement-versus-actual-error calibration. Similar masks are not automatically correct masks.

**Effort:** low for inference fusion, medium for paired-window training. **Main risk:** averaging can erase small structures; correlated predictions can agree confidently while wrong.

**Substantial prior-art overlap:** [RevSAM2](https://arxiv.org/abs/2409.04298) uses reverse propagation for correction. [Reliability-Aware Cross-Prompt Aggregation, MICCAI 2026](https://papers.miccai.org/miccai-2026/0874-Paper1506.html) explicitly addresses accumulation of propagation errors with reliability-based prompt aggregation. Do not claim generic bidirectional consistency or confidence-weighted fusion as a new idea. This direction is the weakest standalone novelty and the easiest useful baseline.

## 8. Required experimental foundation

### Stage 0 — Make the baseline trustworthy

1. Freeze a code revision, checkpoint identity, cache version, label mapping, prompt protocol, and evaluation script. Preserve existing fold runs as historical experiments.
2. Verify preprocessing, orientation, intensity normalization, label encoding, slice indexing, and prompt coordinate transforms against original volumes. Audit the last-slice boundary check in the evaluator against batched tensor dimensions.
3. Implement real NSD using correctly ordered spacing and a declared tolerance in millimeters; add HD95 and explicit handling of absent organs and empty predictions. Verify on identical masks, shifted masks, and empty-mask cases.
4. Evaluate the official pretrained checkpoint and the local fine-tuned checkpoint under the same protocol before diagnosing the performance gap.
5. Audit any shared pretrained data overlap with evaluation subjects. Fold separation prevents local fine-tuning leakage, but cannot prove that foundation-model pretraining never saw a subject. Report unknown overlap honestly.
6. Use a lossless label cache if the JPEG audit reveals corruption. Treat cache corrections as baseline changes and rerun matched comparisons; do not count repaired data as algorithmic novelty.

### Stage 1 — Diagnose errors without expensive retraining

Save per-slice predictions, prompt trajectories, slice distance from initialization, and empty-mask events. Compare union and mean fusion. Stress initial boxes with translation, inward cropping, outward enlargement, and asymmetric edge changes at prespecified severities. Compare central, off-center, and near-end initial slices under an explicit simulated-user protocol.

Use development patients for exploration. Because folds 1/2 results have already informed discussion, they are not pristine final confirmation sets. Reserve external data or prospectively locked evaluations for stronger confirmation.

### Stage 2 — Test the two strongest mechanisms separately

Train Direction A and Direction B separately with small, prespecified pilot budgets. Continue only if the expected failure mode improves on inner-validation patients. A total Dice gain without spacing robustness or propagation recovery is weaker evidence for the proposed mechanism.

### Stage 3 — Combine only supported components

| Experiment | Spacing adaptation | Rollout training | Benefit-based correction |
|---|---|---|---|
| B0 | No | No | No |
| B1 | Yes | No | No |
| B2 | No | Yes | No |
| B3 | Yes | Yes | No |
| B4 | Yes | Yes | Yes |

Hold fusion constant across this table. Analyze Direction D in a separate small ablation. Compare B4 with equally budgeted correction baselines; its extra prompts must not be credited as an architectural gain over single-prompt B0–B3.

### Stage 4 — Locked evaluation and reporting

For each outer CV fold, tune thresholds, calibration, early stopping, corruption schedules, and selector parameters using only an inner split of its training volumes. Then lock settings and evaluate its held-out patients. Use patient-level splits, never slice-level splits. If refitting on all 24 outer-training cases, predefine the training duration from inner validation.

Report the four current organs first: liver=6, stomach=7, left kidney=3, spleen=1. Expand to smaller or difficult organs with verified label mappings if available. Keep point and box results separate.

Report per-organ Dice, NSD, HD95, per-fold means, and out-of-fold per-patient scores. Distinguish SD across folds from SD across patients. Use paired patient-level differences and patient-level bootstrap intervals; slices, repeated prompts, and resampled copies are not independent patients. State the limitation of only 30 BTCV volumes.

Measure preprocessing, image encoding, sequential decoding, and end-to-end latency separately, plus peak GPU memory, trainable parameters, prompt count, and extra decoder calls. Use identical hardware, warm-up, and CUDA synchronization for timing. A training-free method can still be computationally expensive.

Benchmark the unchanged Slide-SAM, the matched local LoRA baseline, the proposed method, and a feasible modern medical SAM2 baseline. A supervised nnUNet can provide task context, with its different supervision and interaction setting clearly stated. External validation strengthens any generalization claim.

| Priority | Work | Deliverable / decision |

| 1 | Baseline audit and trajectory logging | Trustworthy reference results and identified failure types |
| 2 | Union versus mean fusion; noise and spacing tests | Low-cost evidence on what actually fails |
| 2a | Team's box-padding × conditional-resampling experiment (Section 10) | Separate simple preprocessing/prompt gains from learned-module gains |
| 3 | Direction B pilot | Establish whether exposure to predicted prompts improves recovery |
| 4 | Direction A pilot | Establish whether physical conditioning adds value beyond resampling/augmentation |
| 5 | A+B controlled ablation | Test whether the mechanisms complement each other |
| 6 | Direction C | Demonstrate better use of a fixed interaction budget |
| 7 | Locked CV and external evaluation | Evidence suitable for a research claim |

Suggested working title: **Reliable Slice Propagation for Interactive Medical Segmentation under Variable Spacing and Imperfect Prompts**.

Possible contribution statements, conditional on positive evidence:

- A physical-distance-conditioned context adapter that reduces degradation as inter-slice separation changes.
- A short-rollout adaptation strategy that reduces downstream errors from model-generated prompts.
- A corrective-prompt policy that improves volume segmentation per interaction by predicting downstream benefit.

Do not promise a Dice increase before testing. If simple augmentation or mean fusion performs equally well, report that finding and revise the claimed mechanism. Implementing all four ideas is not necessary; a well-supported A+B study can be more convincing than many modules with unclear individual effects.

## 10. Team's original plan — Box padding and adaptive z-spacing handling

Added from the team's proposal on 26 September 2026. Both ideas are directly relevant, with a narrower implementation scope than the learned methods above.

| Team proposal | Relationship to the proposed directions | Appropriate claim at this stage |
|---|---|---|
| Prompt noise robustness through automatic box padding | Addresses the prompt-error problem in Direction B; provides a simple inference-only comparator to recovery training | A practical robustness intervention, not rollout training or a proven new algorithm |
| Conditional resampling for large through-plane spacing | Direct preprocessing baseline for Direction A | A metadata-driven spacing-normalization intervention, not learned adaptive context |
| Combined 2×2 study | Tests whether these two interventions complement or interfere with each other | A controlled empirical study; publication novelty depends on evidence and comparison with existing methods |

### 10.1 Task 1 — Prompt noise robustness via box padding

**Hypothesis:** mask-derived propagation boxes can omit peripheral anatomy as the organ changes across slices. A small expansion may improve boundary recall and delay erroneous termination. Frequent inward collapse and its contribution to the current errors still need to be measured; they are not established merely by the proposed explanation.

**Team's proposed formula, preserved:** for image width `W`, height `H`, and a box `(x0, y0, x1, y1)` in that image's coordinate system:

```text
x0′ = max(0,     x0 − p × W)
x1′ = min(W−1,   x1 + p × W)
y0′ = max(0,     y0 − p × H)
y1′ = min(H−1,   y1 + p × H)
```

Use `p=0.05` in the main experiment; test `p=0.10` as a separately declared sensitivity experiment. This definition pads **each side by a fraction of the full image dimensions**. On a 512×512 image, 5% adds 25.6 pixels on each side before clipping; it is not a 5% increase in the box's total width.

An alternative is box-relative padding, using `p × (x1−x0)` horizontally and `p × (y1−y0)` vertically. Five percent per side then increases each box dimension by approximately 10% before clipping. Preserve the image-relative formula for the team's primary study and label a box-relative comparison separately; do not silently exchange the definitions. Declare the coordinate grid, rounding convention, and clipping behavior.

**Important source finding:** `core/volume_predictor.py::generate_prompts_from_previous_masks` already calls `datasets/data_engine.py::BoxPromptGenerator.enlarge`. The inspected implementation hardcodes 5% box-relative margins but subtracts a margin from `x1` and `y1`, uses `margin_x` for `y0`, and uses `margin_y` for `x1`. Its `margin` argument is unused. This does not implement symmetric expansion, and the current propagation path cannot be described as unchanged zero padding. Actual effects on segmentation have not been tested.

**Baseline handling:** retain the unchanged code as a historical reference. Separately implement an explicit, coordinate-correct `p=0` path for all zero-padding factorial cells. The padding comparison must change only `p`, not signs, coordinate conventions, or clipping logic between cells. Report the difference between historical behavior and corrected zero padding separately as an implementation correction.

**Flow:**

```text
Predicted endpoint mask
    → tight bounding box
    → configured image-relative padding
    → clip to the actual coordinate-grid bounds
    → next-window prediction
    → log box dimensions, recall, and propagation termination
```

Apply padding only to automatically propagated boxes in the main experiment. Keep the initial user/simulated-user prompt identical across cells and leave ground-truth labels unchanged. Padding initial boxes is a different intervention and should be a separate ablation.

**Limitations:** padding cannot revive a mask that was already rejected by the pre-box area threshold or is empty. Larger boxes can include competing anatomy and increase false positives. Measure boundary recall, precision, terminal-slice coverage, and premature-stop frequency rather than assuming all enlargement is beneficial.

### 10.2 Task 2 — Adaptive anisotropic z-spacing handling

**Team's proposed rule:** read physical spacing from NIfTI geometry. If spacing along the intended through-plane axis exceeds 5.5 mm, resample that axis toward 3.0 mm before running the three-slice predictor. Otherwise preserve the original grid.

Two terminology corrections are important. Voxel spacing describes sample-center separation and should not automatically be equated with acquisition slice thickness. Changing only z to 3.0 mm is through-plane spacing normalization; it is not isotropic unless x and y are also 3.0 mm. Treat 5.5 mm and 3.0 mm as proposed experimental settings, not universal clinical thresholds.

**Flow:**

```text
Original NIfTI image and physical geometry
    → identify/canonicalize the intended slice axis
    → check through-plane spacing
    → if >5.5 mm, construct a physical reference grid near 3.0 mm
    → linearly resample image; nearest-neighbor resample labels if needed
    → map the initial prompt into the corresponding physical location
    → run Slide-SAM propagation
    → map predictions back to the original grid
    → evaluate against untouched original-grid ground truth
```

Preserve direction/orientation, origin, x/y geometry, and physical coverage, documenting any grid-size rounding. Do not assume array axis 0 or the smallest array dimension is anatomical z: the existing predictor's shape-based orientation heuristic needs explicit handling when resampling changes dimensions.

Use linear interpolation for image intensities and nearest-neighbor for discrete labels. For prediction restoration, use nearest-neighbor if the pipeline exports only binary masks; alternatively restore probabilities linearly and threshold once, with that policy fixed across the study. Any resampled labels used for simulated prompts remain discrete; final scoring uses the original labels.

Keep the same physically located initial prompt across variants. Do not recompute a more favorable ground-truth box on a different resampled slice for the ON condition. Record how the physical prompt plane is mapped to the nearest output slice.

**Expected benefit, stated carefully:** interpolation may reduce abrupt numerical changes between model inputs. It creates interpolated samples and can smooth boundaries; it does not recover missing anatomical information or guarantee anatomical fidelity. The benefit must outweigh interpolation artifacts and extra inference work. Resampling from 6 mm to 3 mm approximately doubles the slice count for the same physical coverage, so report latency and memory.

**Implementation locations:** add an optional geometry-preserving preprocessing/restoration wrapper around the fold loader and volume predictor. Preserve original geometry alongside working-grid geometry. Keep the model checkpoint fixed initially to isolate inference preprocessing; retraining on resampled data is a later, separate experiment.

### 10.3 Strict 2×2 factorial experiment

Use one fixed checkpoint per fold, identical initial prompts, identical held-out patients, and identical model/postprocessing settings except for the two named factors.

| Experiment | Propagated box padding | Conditional through-plane resampling |
|---|---|---|
| B00 — Controlled baseline | Explicit `p=0` | OFF |
| B10 — Task 1 only | Image-relative `p=0.05` per side | OFF |
| B01 — Task 2 only | Explicit `p=0` | ON when spacing >5.5 mm; target ≈3.0 mm |
| B11 — Combined | Image-relative `p=0.05` per side | ON when spacing >5.5 mm; target ≈3.0 mm |

Also report **H — historical implementation**, with its existing `enlarge()` behavior and resampling OFF. H is outside the four-cell matrix; including it exposes the effect of the implementation correction without confounding the factorial comparison.

For a higher-is-better metric `M`, calculate paired patient-level contrasts:

```text
Padding effect without resampling:      M10 − M00
Resampling effect without padding:     M01 − M00
Combined gain:                         M11 − M00
Interaction:                           M11 − M10 − M01 + M00
```

A positive interaction estimate suggests more-than-additive benefit on that metric scale; uncertainty intervals are needed before drawing a firm conclusion. Report main effects averaged over the other factor as well if presenting a formal factorial analysis. Reverse interpretation appropriately for error or distance metrics where lower is better.

### 10.4 Evaluation and decision criteria

1. Audit the number of native scans above 5.5 mm before starting. If none qualify, the resampling factor is inactive and cannot be evaluated on that cohort. Report all-patient and eligible-subgroup results separately.
2. If needed, create declared synthetic thick-spacing stress tests from held-out scans, keeping each patient's derivatives together. These are robustness simulations, not substitutes for native thick-slice external validation or extra independent patients.
3. Measure original-grid Dice, correctly implemented NSD with a declared millimeter tolerance, HD95, foreground recall/precision, terminal-region coverage, and premature-stop frequency. Declare how terminal regions are defined before testing.
4. Use the same noisy initial-prompt realizations across all four cells when testing robustness. Keep clean-prompt and corrupted-prompt results separate. Test inward cropping explicitly.
5. Select padding variants, thresholds, and restoration choices on inner-validation data only. Keep the primary `p=0.05`, >5.5 mm trigger, and ≈3.0 mm target fixed for the confirmatory comparison, or clearly document any validation-driven revision before test evaluation.
6. Report patient-level paired differences with uncertainty, runtime, peak memory, and resulting slice count. Check whether recall gains are purchased with excessive false positives.

**How this strengthens the larger research plan:** if fixed padding succeeds, test whether rollout training still adds value beyond it. If simple resampling succeeds, require a learned spacing adapter to outperform that baseline at comparable compute. If the two simple changes solve the observed problem, present that evidence without inventing an unnecessary architectural novelty.
