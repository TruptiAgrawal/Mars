Step 1. Generate the 5 BTCV-only volume-level folds

We will create one deterministic 5-fold partition of the 30 BTCV volumes.

Each fold:

24 training volumes
6 held-out test volumes

The split is at the volume/patient level, not at the slice level.

For example:

Fold 1:
  Train = 24 volumes
  Test  = img0001 ... img0006

Fold 2:
  Train = 24 volumes
  Test  = img0007 ... img0012

...

The exact IDs should be generated from the actual files rather than manually assumed.

Files created
dataset_list/
├── 01_BTCV_all30_train.txt
├── fold1/
│   ├── 01_BTCV_train_4to1.txt
│   └── 01_BTCV_test_4to1.txt
├── fold2/
│   ├── 01_BTCV_train_4to1.txt
│   └── 01_BTCV_test_4to1.txt
...
└── fold5/
    ├── 01_BTCV_train_4to1.txt
    └── 01_BTCV_test_4to1.txt
Important

Do not create WORD_50_train.txt in these folders.

This experiment is:

BTCV-only 5-fold cross-validation

not BTCV + WORD.

WORD belongs to a separate experiment.

The WORD_50_train.txt requirement comes specifically from cache_dataset3d_e2.py, which was written for the BTCV + WORD E2 experiment. We should not distort the CV experiment just to satisfy that loader.

Step 2. Mathematically verify the folds

Before building any cache or training anything, run an independent verification.

We need to establish all of the following:

2.1 Exactly 30 unique BTCV volumes
|V| = 30
2.2 Every fold has 24 train + 6 test

For every k:

|Train_k| = 24
|Test_k|  = 6
2.3 No within-fold leakage

For every fold:

Train_k ∩ Test_k = ∅
2.4 Every volume is held out exactly once

Across all five test sets:

Test_1 ∪ Test_2 ∪ ... ∪ Test_5 = V

and:

|Test_1 ∪ ... ∪ Test_5| = 30

with each volume appearing exactly once.

2.5 Deterministic split

Running the split generator again must produce exactly the same manifests.

We should explicitly compare the generated files if necessary.

2.6 Verify against the actual BTCV files

The manifests must correspond to actual:

datasets/01_BCV-Abdomen/Training/img/*.nii.gz

and corresponding labels.

No training starts before this verification passes.

Step 3. Build one shared BTCV cache containing all 30 volumes

We should build one physical cache:

btcv_cross_validation/cache/all30/

containing cached samples derived from all 30 BTCV volumes.

This is deliberately different from training on all 30.

The cache is merely a storage representation.

The training loader will subsequently select only the 24 volumes belonging to the current fold.

Conceptually:

                         BTCV 30 volumes
                               │
                               ▼
                       shared cache/all30
                               │
             ┌─────────────────┼─────────────────┐
             ▼                 ▼                 ▼
          Fold 1            Fold 2             ...
         24 volumes        24 volumes
Why this is scientifically cleaner

We don't want five separate cache-generation processes introducing unnecessary differences.

All folds should use:

the same raw data,
the same preprocessing,
the same cache representation,
the same image/slice extraction.

Only the volume membership of the training set should change.

Important distinction

Building the cache from all 30 volumes is not data leakage by itself.

The cache contains preprocessing representations of the volumes. Leakage would occur if samples from the six held-out volumes were actually supplied to the training dataset.

Therefore Step 4 is critical.

Step 4. Create a dedicated BTCV CV dataset loader

This is the most important implementation step.

We should not use:

datasets/cache_dataset3d_e2.py

because that loader explicitly implements:

BTCV + WORD-50

and requires:

WORD_50_train.txt

Instead, create a dedicated loader, for example:

datasets/cache_dataset3d_cv.py
Before modifying this file

We will first inspect the relevant implementation of:

datasets/cache_dataset3d.py
datasets/cache_dataset3d3.py
core/ddp_sub.py

and then explicitly tell you:

File to create: datasets/cache_dataset3d_cv.py
Reason: expose only the BTCV training volumes listed in the current fold while reusing the shared all30 cache.

Only after that approval/confirmation should we create it.

Required behavior

For a given fold:

data_txt_path =
btcv_cross_validation/dataset_list/fold1/

the loader reads:

01_BTCV_train_4to1.txt

and extracts the volume IDs.

Then it scans:

btcv_cross_validation/cache/all30/

and selects only cached samples belonging to those 24 volumes.

Thus:

Fold 1 loader
    ↓
24 BTCV volume IDs
    ↓
all30 cache
    ↓
only samples from those 24 volumes

The six Fold-1 test volumes never enter the training dataset.

Critical audit

The loader should print something like:

CV DATASET AUDIT
Fold: 1
Training volumes: 24
Cached training samples: XXXXX
Excluded held-out volumes: 6

Ideally it should also verify that zero selected cache samples belong to the six held-out volumes.

This makes leakage detectable rather than merely assumed away.

Step 6. Add a fold-specific test/evaluation path

This needs to be handled separately from training.

For each fold:

Fold N training:
    24 volumes

Fold N evaluation:
    6 held-out volumes

The evaluation script must explicitly select:

01_BTCV_test_4to1.txt

for that fold.

This is important because merely loading the model checkpoint with the normal BTCV evaluator does not automatically guarantee that it evaluates only the six held-out volumes.

Before creating the evaluation scripts, we should inspect:

test/volume_eval_sublora.py

and the dataset/evaluation classes it calls.

We already know there is a potentially dangerous issue in the proposed snippet:

label_idx: 2

and the comment:

2 = liver

is wrong for our BTCV mapping.

Our verified mapping is:

1 = Spleen
2 = Right Kidney
3 = Left Kidney
6 = Liver
7 = Stomach

So we should not copy that evaluation configuration unchanged.

Step 7. Define the evaluation targets

For the Slide-SAM baseline comparison, evaluate the four organs used in the paper:

Liver
Stomach
Left Kidney
Spleen

Corresponding BTCV labels:

Liver       = 6
Stomach     = 7
Left Kidney = 3
Spleen      = 1

Right Kidney:

2

is not one of the four paper-aligned organs for this particular baseline evaluation.

This also means the previous specific_label: [2] configuration should not automatically be interpreted as the paper's four-organ experiment.

Step 9. Aggregate the five folds

After all five folds:

For each organ:

Fold 1 Dice
Fold 2 Dice
Fold 3 Dice
Fold 4 Dice
Fold 5 Dice
----------------
mean ± SD

Do the same for the other metrics we use.

The final CV result should report:

mean across folds
standard deviation across folds

rather than selecting the single best fold.

This gives us a much stronger statement about variability across the 30 BTCV volumes.
